| Remote command execution policy | Implemented | security/remote_command_policy.py, runtime.py, state/store.py, policy/remote_fetch.py, security/remote_command_responses.py | Authenticated commands pass through a runtime-owned execution policy. `REFRESH_POLICY` executes the signed DevicePolicy refresh path; `APPLY_POLICY` fetches an HTTPS-referenced bundle, matches SHA-256, and reuses signed DevicePolicy verification. `SET_THRESHOLD` is executable with Tier D startup-sensitivity and active-suppression guards. Executable commands support `args.dry_run=true` for verified, audited, non-mutating preflight checks. SMS/WhatsApp return concise operator feedback for execution outcomes. All other commands remain audit-only. |
| SET_THRESHOLD remote command | Implemented | security/threshold_guard.py, runtime.py | Tier D threshold keys are protected by a startup-sensitivity guard: remote changes may make Tier D more sensitive but not less sensitive than startup config. Direction-ambiguous Tier D expressions fail closed. Active-suppression checks run against recent sensor readings. |
| Runtime ContextEnricher for prompt snapshots | Implemented | reasoning/context_enricher.py, state/store.py, reasoning/elevator.py, config.py, runtime.py | Disabled by default. When `reasoning.context_enricher.enabled: true`, appends the most-recent reading from every other sensor on the device to the prompt before local SLM or gateway inference. Snapshot is bounded by `staleness_window_ms` (evaluated at prompt-build time, not event-emit time), capped at `max_entries` (1–20), and optionally filtered to `include_sources`. All injected values are sanitised with the same regex used for event sensor fields. Enrichment failure is silent: any exception returns the original prompt and logs a WARNING so the runtime never halts. Tier D triggers fire before `_build_prompt` is called — enricher is never invoked on safety-critical paths. |
