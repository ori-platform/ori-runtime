# Ori Runtime — v1.0.0 Release Notes

## Release Type

Stable runtime release (`v1.0.0`)

## Compare

`v0.9.0-beta.2...v1.0.0`

https://github.com/ori-platform/ori-runtime/compare/v0.9.0-beta.2...v1.0.0

## Summary

Ori Runtime v1.0.0 freezes the first stable edge-runtime contract for physical
actuation, local reasoning, gateway integration, and product/demo consumers.
The runtime is now ready to be consumed by downstream FastAPI services through the
stable `ori.integration` rule-evaluation boundary while deployed edge nodes
continue to communicate with gateways over the runtime-owned MQTT contracts.

The core posture is unchanged: Tier D safety is deterministic and local, Tier C
requires approval, Tier B physical autonomy requires explicit policy, local SLM
confidence is non-authoritative, and cloud reasoning is a gateway backend rather
than a runtime dependency.

## Included Since v0.9.0-beta.2

- Runtime-gateway integration hardening:
  - deterministic gateway escalation policy before local SLM inference
  - authenticated runtime-gateway MQTT envelopes with HMAC and replay windows
  - TLS support for gateway MQTT clients
  - AES-GCM encryption for sensitive export responses
  - gateway heartbeat subscription and runtime node heartbeat publishing
- Runtime audit/export surfaces:
  - bounded reasoning-log export
  - action/reasoning correlation IDs for Tier B post-action joins
  - alert outbox retry policy surfaced in health snapshots
- Product/demo boundary:
  - `ori.integration.RuleEvaluationRequest`
  - `ori.integration.RuleEvaluationSession`
  - `ori.integration.evaluate_sensor_reading(...)`
  - installed-wheel proof that bundled skills resolve from packaged data files
- Skill/runtime intelligence:
  - time-of-week site baseline suppression over hourly retained history
  - weighted compaction writes for trustworthy baseline buckets
  - retail occupancy optimizer bundled skill
  - optional runtime ContextEnricher for bounded cross-sensor prompt snapshots
- Release and supply-chain readiness:
  - scoped mypy gate over runtime contract-boundary modules
  - release wheel smoke test in CI on Python 3.12
  - modern SPDX license metadata in `pyproject.toml`

## Stable Runtime Contract

v1.0.0 stabilizes these runtime-facing integration points:

- Skill YAML action-tier contract and loader validation rules
- `SensorReading` and `OriEvent` event data model
- Tier A/B/C/D action authority invariants
- Runtime-owned MQTT gateway reasoning/export/heartbeat contracts
- Runtime bounded export surfaces for gateway/cloud consumers
- `ori.integration` in-process rule-evaluation boundary for demos and product tests

## Explicit Non-Goals

v1.0.0 does not mean every companion repo is feature-complete. Gateway,
SDK, dashboard, product provisioning, and cloud surfaces can continue iterating while
using the stable runtime contracts above.

Repo-wide mypy is also not claimed as complete in v1.0.0. The enforced gate is
currently scoped to contract-boundary modules consumed by gateway, product provisioning,
ori-specs, and future cloud sync. Full-repo mypy remains a separate hardening
milestone because HAL, sandbox internals, hardware adapters, tests, and the full
runtime loop have different typing risk profiles.
